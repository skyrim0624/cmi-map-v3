# 需求文档

## 1. 应用概述

- **应用名称**：CMI Map
- **应用描述**：一款面向清迈华人社区的共建生活地图移动端 Web 应用。社区成员在地图上标记自己推荐的地方,留下推荐理由与照片,共同绘制一张属于社区的清迈生活地图。整体风格极简、轻盈、有温度,像一本精致的手账本。

---

## 2. 产品原则与边界

CMI Map 不做广告地图，也不做 AI 行程工具；它是一张让用心生活的人彼此留下痕迹、产生默契的清迈地图。当前完整原则见 [产品原则收敛计划](./product-principles.md)。

**功能取舍边界**
- 推荐是核心内容，但推荐应是个人经验的留下，而不是商家广告、榜单排名或模板化点评。
- 不引入普通商家广告位；未来商业化必须服务于地图气质，例如精选合作、赞助路线、贴纸/手账个性化，而不是信息流广告。
- AI 路线规划暂不作为核心方向；若加入，只能作为辅助发现工具，不能把产品变成旅行规划机器人。
- 优先推进纯净地点推荐与高质量推荐语、黑魂式留言/陌生人默契、手账式个人地图/旅行日记、轻量社交连接。

**后续功能过滤问题**
- 这个功能会让地图更有人味，还是更像大众点评？
- 这个功能会让用户更想留下真实经验，还是只是在消费信息？
- 如果一年后继续维护它，创作者会更喜欢这个产品，还是更厌烦它？

---

## 3. 用户与使用场景

### 3.1 目标用户
- 居住或旅居清迈的华人社区成员
- 希望发现清迈本地隐藏好去处的用户

### 3.2 核心使用场景
- 用户无需登录即可浏览地图,发现社区成员推荐的地点
- 用户切换到列表模式,按分类筛选感兴趣的推荐
- 用户在地图上任意位置标记推荐地点,填写推荐理由并上传照片
- 用户查看个人页面,回顾自己贡献的所有推荐
- 用户在个人页面上传或更换头像

---

## 4. 页面结构与功能说明

### 4.1 整体页面结构

```
CMI Map
├── 登录 / 注册界面
├── 查看界面(登录后默认首页)
│   ├── 地图模式(默认)
│   │   └── 地点预览卡片(底部滑入)
│   └── 列表模式
├── 地点详情页
├── 补一句推荐页
├── 推荐人地图页
├── 标记界面
└── 个人页面
```

**全局交互规则**
- 不使用底部 Tab 栏
- 地图、列表和地点详情允许未登录用户浏览
- 推荐人地图允许未登录用户浏览，用于展示某个人留下的清迈品味轨迹
- 标记地点、给已有地点补一句、点赞、想去、盖戳、个人页面等互动能力需要登录
- 未登录用户触发互动操作时跳转登录页,登录后回到原目标页面

---

### 4.2 登录 / 注册界面

**布局**
- 顶部：应用标题「CMI Map」
- 中部：邮箱输入框、密码输入框
- 登录按钮(强调色 #9B8EC6)
- 底部切换文字：「还没有账号?立即注册」/ 「已有账号?返回登录」

**登录功能**
- 输入邮箱 + 密码,点击登录按钮
- 校验邮箱格式与密码非空,不通过时提示错误信息
- 登录成功后跳转至查看界面地图模式
- 无验证码

**注册功能**
- 输入邮箱 + 密码 + 用户名(昵称)
- 校验邮箱格式、密码非空、用户名非空
- 注册成功后自动登录并跳转至查看界面地图模式
- 无验证码

---

### 4.3 查看界面 · 地图模式(默认首页)

**布局**
- 顶部左侧：应用标题「CMI Map」,无副标题
- 顶部右上角：列表图标按钮,点击切换到列表模式
- 主体区域：Leaflet 地图全屏显示,但首页默认只展示精选点位，避免第一眼被密集标记淹没
- 底部上方：CMI Picks 决策面板，包含「今天去哪」、吃饭 / 咖啡 / 办事 / 闲逛 / 放松等场景入口，以及「CMI 常去」「完整地图」
- 左下角：圆形小按钮,图标为 ✏️,点击切换到标记界面
- 底部正中央：圆形区域内显示简笔画箭头图标(约 40px),点击进入个人页面

**地图标记点**
- 默认展示精选推荐地点,以彩色标记点呈现；点击「完整地图」后展示所有已提交的推荐地点
- 不同分类对应不同颜色：
  - 吃饭 = 橙色
  - 咖啡 = 棕色
  - 户外 = 绿色
  - 拍照 = 粉色
  - 涂鸦 = 紫色
  - 市集 = 蓝色
  - 放松 = 青色
  - 运动 = 红色
  - 宝藏 = 灰色

**地点预览卡片**
- 点击地图上某个标记点,从底部滑入一张预览卡片
- 卡片内容(从上到下)：
  - 推荐理由文字(最大最醒目,带引号,占卡片主要空间)
  - 地点名称 + 分类图标(中等大小)
  - 推荐人名字(小字,格式：「—— 名字」)
  - 若有照片,显示小缩略图
- 点击预览卡片 → 进入地点详情页

---

### 4.4 查看界面 · 列表模式

**布局**
- 点击右上角列表图标进入,右上角图标切换为地图图标(点击切回地图模式)
- 顶部标题下方：横向滚动的分类筛选胶囊按钮
  - 包含「全部」+ 9 个分类：🍜 吃饭 | ☕ 咖啡 | 🏔️ 户外 | 📸 拍照 | 🎨 涂鸦 | 🛍️ 市集 | 💆 放松 | 🏃 运动 | ✨ 宝藏
  - 默认选中「全部」
  - 点击某分类,列表仅展示该分类的推荐
- 下方：垂直滚动的推荐卡片列表
- 底部正中央：简笔画箭头图标(圆形区域,约 40px)

**推荐卡片**
- 左侧：推荐照片方形缩略图(圆角 12px);无照片时显示对应分类 emoji 作为占位
- 右侧上方：推荐理由文字(带引号,卡片最主要内容)
- 右侧下方：📍 地点名称 —— 推荐人名字(小字)
- 卡片间距充足,保持呼吸感
- 点击卡片 → 进入地点详情页

---

### 4.5 地点详情页

**布局(从上到下)**
- 左上角：返回箭头,点击返回上一页
- 顶部：推荐照片大图展示;多张照片支持左右滑动轮播;无照片时显示分类色块占位
- 推荐理由文字(大号字体,带引号的引用样式,页面最核心内容)
- 推荐人名字(小字,格式：「—— 名字」)
- 地点名称(加粗) + 分类标签(胶囊样式)
- 多人推荐展示：若同一地点有多条推荐,每条以独立引用卡片形式展示
- 闭环入口：用户可点击「我也来补一句」,进入已有地点补充推荐流程
- 底部：导航、Grab、Bolt 操作按钮,点击后使用地点坐标打开对应导航或打车入口

---

### 4.6 补一句推荐页

**布局**
- 顶部：返回按钮 + 标题「我也来补一句」+ 地点名
- 上方：原始推荐卡片,显示该地点的一条代表性推荐
- 中部：文本输入框,只要求用户写一句新的推荐或补充体验
- 下方：可选照片上传
- 底部：提交按钮「留下这一句」

**业务规则**
- 从地点详情页进入,自动沿用该地点的地点名、坐标和分类
- 不重新选点,不重新填写地点名称
- 提交后写入现有 `recommendations` 表,并回到地点详情页高亮刚留下的推荐
- 本功能不新增数据库表、不依赖 V2/V3 的 `meet_signals` 或公开/私密字段

---

### 4.7 推荐人地图页

**布局**
- 顶部：返回按钮 + 标题「TA 的清迈地图」+ 推荐人名字
- 第一屏：推荐人头像字母、贡献地点数、偏爱分类、代表性一笔推荐
- 中部：品味轨迹分类筛选，按该推荐人真实贡献聚合分类
- 下方：「跟着 TA 逛」列表，展示 TA 留下的所有推荐
- 点击推荐卡片 → 进入对应地点详情页

**设计目标**
- 不做强社交关系链，先让用户感受到“这个人留下的清迈是什么样子”
- 让推荐人从列表里的落款，变成可继续探索的路径
- 后续可接入“跟着 TA 的地图逛逛”“想找 TA 带路”等低压力连接

---

### 4.8 标记界面

**布局**
- 顶部：文字「在地图上画一笔」
- 主体区域：Leaflet 地图,中央显示十字准星标记
  - 进入时优先定位到用户当前 GPS 位置
  - 用户可自由拖动地图,将十字准星移动至地图任意位置进行标记,不限于当前所在位置
- 左下角：切换按钮图标变为 🔍,点击切回查看界面
- 底部正中央：简笔画箭头图标(圆形区域,约 40px)

**录入流程**
- 拍照或从相册选择照片
- 可跳过照片,直接进入快速文字推荐
- 实时拍摄优先使用 GPS 坐标;相册照片进入手动地图校准
- 支持语音输入推荐理由,也支持直接手动输入文字
- 从输入内容中自动拆分地点名称和推荐理由
- 最后选择分类并提交

**底部操作按钮**
- 「📷 拍照」：打开相机或相册
- 「✅ 画上去」：提交按钮,强调色(#9B8EC6)

**提交成功反馈**
- 显示温馨提示：「你的这一笔已经画上去了 🎉」
- 自动切换回查看界面的地图模式

---

### 4.8 个人页面

**布局(从上到下)**
- 顶部：用户头像(大号,圆形) + 用户名字
- 头像右下角：编辑图标按钮,点击进入头像上传功能
- 统计数据：已贡献 X 个推荐
- 「我的推荐」列表：展示该用户贡献的所有推荐(卡片形式,与列表模式卡片样式一致)
- 底部：返回按钮

**头像上传功能**
- 点击头像右下角编辑图标,触发头像上传
- 支持从相册选择或拍照上传
- 上传成功后,头像立即更新显示
- 若用户未上传头像,显示默认头像占位图

## 5. 业务规则与逻辑

### 5.1 地点坐标记录
- 用户在标记界面拖动地图,十字准星所指位置即为标记坐标,可为地图上任意位置
- 提交时记录该坐标,用于在地图模式中渲染标记点

### 5.2 用户名与身份
- 用户注册时填写的用户名作为推荐人名字,自动填入标记界面的名字字段,不可手动修改
- 个人页面展示当前登录用户的推荐记录

### 5.3 用户头像
- 用户可在个人页面上传或更换头像
- 头像在个人页面顶部显示
- 未上传头像时显示默认头像占位图
- 头像数据持久化存储

### 5.4 多人推荐同一地点
- 同一地点(以地点名称为唯一标识)可被多人推荐
- 地图上该地点仅显示一个标记点
- 地点详情页中以独立引用卡片形式展示所有推荐条目

### 5.5 导航跳转
- 「导航」按钮点击后,携带地点坐标跳转至 Google Maps
- Grab / Bolt 按钮会复制地点名并尝试打开对应 App 或网页入口

### 5.6 分类筛选
- 列表模式下,选中某分类时仅展示该分类的推荐卡片
- 选中「全部」时展示所有推荐

### 5.7 登录态保持
- 用户登录后保持登录状态,关闭页面后再次访问无需重新登录
- 未登录用户可继续浏览公开页面；触发互动能力时进入登录流程

## 6. 异常与边界情况

| 场景 | 处理方式 |
|------|----------|
| 用户未授权 GPS 定位 | 可从相册选择照片,或进入手动地图校准来选择坐标 |
| 浏览器不支持语音识别 | 用户可直接在文字输入框填写地点名和推荐理由 |
| 提交时推荐理由或地点名称为空 | 表单校验提示,阻止提交 |
| 提交时分类未选择 | 表单校验提示,阻止提交 |
| 上传照片超过 3 张 | 限制选择,超出部分不可添加 |
| 地点无照片 | 列表卡片左侧显示分类 emoji 占位;详情页顶部显示分类色块占位 |
| 当前用户无推荐记录 | 个人页面「我的推荐」区域显示空状态提示 |
| 网络异常导致提交失败 | 提示用户提交失败,保留表单内容,支持重新提交 |
| 注册时邮箱已被使用 | 提示「该邮箱已注册,请直接登录」 |
| 登录时邮箱或密码错误 | 提示「邮箱或密码不正确,请重试」 |
| 头像上传失败 | 提示用户上传失败,保持原头像不变 |
| 用户未上传头像 | 显示默认头像占位图 |

## 7. 视觉规范

- **底色**：白色,干净明亮,有呼吸感
- **强调色**：柔和薰衣草紫 #9B8EC6,仅用于切换按钮、提交按钮、选中态等强调元素
- **个人标志图标**：简笔画箭头,置于底部正中央圆形区域(约 40px),替代原用户头像
- **用户头像**：圆形,显示在个人页面顶部,大号尺寸
- **卡片圆角**：12px,轻微阴影
- **字体**：现代无衬线中文字体
- **推荐理由文字**：全应用最重要的内容,字号最大,行间距舒适,不被其他元素挤压
- **整体原则**：极简、轻盈、有温度,无多余装饰元素,每个像素服务于内容

## 8. 验收标准

- 登录 / 注册界面正常显示,邮箱密码登录与注册流程可正常完成,无验证码
- 未登录状态可浏览地图、列表和地点详情；触发标记、点赞、收藏、盖戳、个人页面等互动时进入登录流程
- 登录成功后跳转至查看界面地图模式,登录态持久保持
- 默认打开查看界面地图模式,Leaflet 地图正常加载并显示所有推荐标记点
- 不同分类标记点颜色与规范一致
- 点击标记点,预览卡片从底部正确滑入,内容完整
- 点击预览卡片,正确跳转地点详情页
- 首页「今天去哪」可跳转到当天推荐地点；「最近痕迹」可跳转到推荐人地图页
- 列表页、地图预览卡片和详情页中的推荐人入口可跳转到 `/people/:userName`
- 列表模式分类筛选功能正常,切换分类后列表内容正确过滤
- 标记界面进入时优先定位至 GPS 位置,用户可自由拖动地图至任意位置进行标记
- 标记界面表单必填项校验有效,提交成功后显示温馨提示并自动切回地图模式
- 标记界面名字字段自动填入当前登录用户名
- 照片上传限制 1-3 张,超出时无法继续添加
- 地点详情页多条推荐以独立引用卡片展示,「导航到这里」按钮跳转百度地图正常
- 个人页面正确展示当前登录用户的所有推荐及贡献数量
- 个人页面头像正常显示,点击编辑图标可触发头像上传功能
- 头像上传成功后立即更新显示,未上传时显示默认头像
- 底部正中央简笔画箭头图标正常显示,点击进入个人页面
- 所有推荐数据及用户头像持久化存储,刷新页面后数据不丢失
- 移动端手机浏览器体验良好,布局无错位

- 推荐点赞、收藏、评论等社交互动功能
