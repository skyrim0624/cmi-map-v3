# CMI Map 社区生活记忆方向

## 核心判断

CMI Map 下一阶段不应继续往“更全的清迈地图”走，而应收束成 **CMI 社区的带地点生活记忆流**。

它最应该绑定的用户心智不是“我想找地方”，而是：

> 我在清迈发现了一个东西，想让这个小圈子知道。

这会把产品从工具型地图拉回社区型产品。真实推荐、吃过的店、活动返图、路上彩蛋、遇到的人和开心时刻，都应该从这个动作里自然长出来。

## 一句话定位

CMI Map 是 CMI 社区的清迈生活地图：记录你在清迈发现的地方、路上遇见的小事、参加过的活动和开心时刻。

更轻的外显文案可以是：

> 把你在清迈遇到的彩蛋，留给后来的人。

## 产品边界

- 不和 Google Maps、小红书、Tripadvisor 拼地点完整度。
- 不把攻略当主增长引擎，攻略只作为社区真实体验的二次整理。
- 不用 AI 批量生成不确定的攻略内容，信息不准会损害社区信任。
- 不把论坛做成主入口，避免产品退化成另一个微信群或本地论坛。
- 所有内容尽量保留地点、时间、事件、人物中的至少一个锚点。

## 核心动作

用户只需要理解一个动作：

> 留个彩蛋。

内部可以继续区分地点推荐、路途点、活动返图、地点补充，但发布前不要把这些概念压给用户。发布流程优先保持短：

1. 拍照或选图。
2. 自动带位置，必要时手动校准。
3. 写一句真实感受。
4. 选择可见范围。
5. 发出。

归档和分类应该发生在表达之后。先让用户留下来，再由系统和运营把内容整理进地点页、活动相册、主题地图或周报。

## 内容三层

- **目的地推荐**：这家店、这个地方真的值得去。
- **路途彩蛋**：路上遇到的小猫、街角的光、奇怪的小店、雨后的路。
- **活动记忆**：同一场活动中多人留下的点、照片、路线和留言。

其中，路途彩蛋是差异化核心。它不是商家百科，也不是正式攻略，而是社区成员在清迈移动、散步、迷路、参加活动时留下的小记忆。

## 首页原则

首页第一屏要回答三个问题：

- 今天清迈发生了什么？
- 我附近有什么真实的人留下的东西？
- 我也可以很轻松地留一个。

首页结构优先级：

1. 社区新鲜事：最近彩蛋、活动返图、地点推荐。
2. 主按钮：留个彩蛋。
3. 轻入口：附近、活动、精选。
4. 地图入口：作为空间浏览方式，不再承担全部产品心智。
5. 攻略和生存包：保留，但下沉为社区背书和实用补充。

## P0 闭环

下一版优先只验证“带地点时刻”的闭环：

- 一个主按钮：留个彩蛋。
- 一个极简发布器：图 + 位置 + 一句话 + 可见范围。
- 一个首页信息流：今天清迈的新鲜彩蛋。
- 一个地图视图：附近彩蛋 + 目的地推荐。
- 一个发布后分享卡：单点卡片先行。
- 一个基础归档：按人、地点、活动聚合。
- 一个活动相册：活动参与者把内容归到同一事件。

## P1

把目的地页改成社区背书页：

- 谁推荐过。
- 推荐理由是什么。
- 最近一次真实体验是什么时候。
- 适合谁、什么时候去、注意什么。
- 附近有什么彩蛋。
- 是否有 CMI 备注或社区合作。

地点页不是商家百科，而是社区经验集合。

## P2

做主题图层和活动滤镜：

- 猫地图。
- 咖啡地图。
- 适合散步地图。
- 雨天地图。
- 夜晚地图。
- 数字游民工作地图。
- CMI 活动记忆地图。

先由官方主题跑通，再考虑用户自定义。

## 两周验证

第一周拉 10-20 个社区熟人，每天一个轻主题，每人每天最多发 1 个。运营每天精选 3 个，生成“今日清迈彩蛋”发群里。

第二周加一个线下活动，比如“外星人探索清迈”，活动后生成活动地图和分享卡。

只看这些指标：

- 有多少人第二次主动发。
- 发完后有多少人愿意把卡片转发到群或朋友圈。
- 看到的人有没有回复“我也想去”“这是哪”“下次带我”。
- 用户更愿意发地点推荐，还是路上彩蛋/开心时刻。
- 发布时卡在哪一步。
- 用户是否在意可见范围。
- 有没有人开始打开地图看别人留下的东西。

## 最重要的一句话

CMI Map 要把“清迈发生在我身上的小快乐”，变成一个可以被小社区看见、保存、归纳、再次发现的地图。
